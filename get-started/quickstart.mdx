Talk to your own voice agent in the browser in about 5 minutes. **No phone
number needed.** Unpod hosts the speech service - microphone capture,
speech-to-text, text-to-speech, and the audio bridge. You write the agent's
brain and run a small browser UI on your machine to speak with it.

This is the fastest way to hear your agent. When you want a real phone call,
follow [Make Your First Phone Call](/get-started/first-phone-call) afterwards.

## Prerequisites

- **Python 3.12+** (the `unpod` SDK requires it).
- **An Unpod API key.** Create an account at [unpod.dev](https://unpod.dev)
  (see [Register](/platform/register)), then generate a key from the
  [API Key](/platform/studio-view/api-key) screen in Studio.
- **An LLM key** - `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` - for the agent's
  brain. It stays on your machine.
- **[Task](https://taskfile.dev)** - the repo's run commands use it
  (`brew install go-task` on macOS).
- **The browser playground UI.** It ships in the `unpod-sdk` repository (not on
  PyPI), so clone the repo to get it:

  ```bash
  git clone https://github.com/unpod-ai/unpod-sdk
  cd unpod-sdk
  ```

## Set your environment

Copy the playground's example env file and fill in three values:

```bash
cp examples/browser_playground/.env.example examples/browser_playground/.env
```

```bash
# examples/browser_playground/.env
SUPERVOICE_URL=wss://api.unpod.io     # Unpod's hosted speech service
UNPOD_API_KEY=sk_...                  # from Studio → API Key
ANTHROPIC_API_KEY=sk-ant-...          # or OPENAI_API_KEY
```

`SUPERVOICE_URL` points the playground at Unpod's hosted speech service and is
also the `base_url` your agent registers against. Use the speech endpoint shown
in your Studio dashboard; `wss://api.unpod.io` is the default.

<Note>
These are the only base URLs you set for this quickstart. For reference, the
Management SDK (`AsyncClient`) reads its own URLs from the environment - **this
is the one place they are documented**:

| Variable | Used by | Default |
|---|---|---|
| `UNPOD_API_KEY` | Everything (auth) | - (required) |
| `UNPOD_SERVICE_BASE_URL` | `AsyncClient` (Management REST) | `https://api.unpod.io/platform` |
| `UNPOD_ORCHESTRATOR_BASE_URL` | `AsyncClient` (orchestrator ops) | derived from the service URL |
| `SUPERVOICE_URL` | Browser playground (speech service + agent `base_url`) | `wss://api.unpod.io` (hosted; the code default `ws://127.0.0.1:9000` is for local development) |

The `AgentRunner` connects over WebSocket; on its own it defaults to
`wss://api.unpod.io` and can be overridden with `UNPOD_ORCHESTRATOR_URL` or a
`base_url=...` argument. Yes, that is a different variable from the client's
`UNPOD_ORCHESTRATOR_BASE_URL` above - one per component, not a typo. The
playground passes `SUPERVOICE_URL` as that argument for you.
</Note>

## Write the agent

This is the only code you write per call. The playground runs
`examples/browser_playground/agent.py`; edit it down to this:

```python
# examples/browser_playground/agent.py
import os
from unpod import AgentRunner, CallContext
from superdialog import LLMAgent

async def entrypoint(ctx: CallContext) -> None:
    ctx.session.dialog_machine = LLMAgent(
        llm="anthropic/claude-haiku-4-5-20251001",
        system_prompt="You are a helpful voice assistant. Keep answers under 3 sentences.",
    )
    await ctx.session.run()

def build_runner() -> AgentRunner:
    return AgentRunner(
        entrypoint=entrypoint,
        agent_id=os.getenv("AGENT_ID", "browser-playground"),
        base_url=os.environ["SUPERVOICE_URL"],   # hosted speech service
        api_key=os.environ["UNPOD_API_KEY"],
    )

async def run_agent() -> None:
    await build_runner().run()
```

<Note>
You don't run this file directly - `task playground` starts the playground
server, which imports it and calls `run_agent()` for you. (`await runner.run()`
is the async form of the blocking `runner.start()` you'll see elsewhere.)
</Note>

Three pieces:

- **`entrypoint(ctx)`** runs once per call. `ctx` is the
  [CallContext](/get-started/core-concepts#callcontext) for that call.
- **The brain** is `LLMAgent` - the simplest brain: a plain LLM with a system
  prompt, no flow graph. Assigning it to `ctx.session.dialog_machine` is how you
  plug your [Agent](/get-started/core-concepts#agent-brain) into the call.
- **`AgentRunner`** is the long-lived process that registers as a worker and
  serves each call. Here it registers against the hosted speech service at
  `SUPERVOICE_URL`. See [AgentRunner](/get-started/core-concepts#agentrunner).

`await ctx.session.run()` keeps the call alive and routes each transcribed turn
to your brain. See [Session](/get-started/core-concepts#session).

<Note>
`LLMAgent` ships in the `superdialog` package, but it is **not** a flow-based
`DialogMachine` - it is the minimal LLM-only brain. You can swap in a pure
adapter (`unpod.adapters.AnthropicAdapter`) or any other brain later; see
[Bring Your Agent](/speech-stack/bring-your-agent).
</Note>

## Run and talk

From the `unpod-sdk/` directory:

```bash
task playground
```

This builds the browser UI, starts it on **http://localhost:9100**, and runs
your agent in-process - registering it with the hosted speech service at
`SUPERVOICE_URL`. The page opens automatically.

Click **Connect**, allow microphone access, and speak. You will see a live
transcript of your words and the agent's replies, plus latency badges on each
turn.

<Accordion title="Run the speech service locally (contributors)">
If you are developing against a local speech stack instead of the hosted
service, run `supervoice` yourself and point `SUPERVOICE_URL` at it:

```bash
# in a separate terminal, from the supervoice repo
cd supervoice
uv run uvicorn supervoice.dev.app:create_dev_app --factory --port 9000
```

```bash
# examples/browser_playground/.env
SUPERVOICE_URL=ws://127.0.0.1:9000
```

The browser-audio routes (`/connect`, `/ws/audio`) are served by
`supervoice.dev.app`, not the platform API. Then run `task playground` as above.
</Accordion>
