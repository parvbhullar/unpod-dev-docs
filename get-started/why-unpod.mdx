**Unpod is the agentic backend for conversational AI.** Apps that talk,
remember and act: voice, messaging, agents and workflows in one SDK, on a
Context Engine that remembers every customer across every channel.

Build the app. Unpod runs everything behind the conversation. Supabase
simplified the backend for traditional apps; Unpod is the backend for apps
that communicate, remember and act.

## A conversational backend is not a normal app backend

Every team building an app that talks assembles three hard layers from
separate systems, then runs them for every user.

<CardGroup cols={3}>
  <Card title="Channels you don't own" icon="radio-tower">
    Each channel has its own carrier, policy and approval rules. Call,
    WhatsApp, SMS and email each have to be built and kept compliant
    separately.
  </Card>
  <Card title="The agent harness" icon="shield-check">
    Running an agent in production means tool calls, guardrails, retries,
    human handoff and evals - all in real time.
  </Card>
  <Card title="Context that compounds" icon="layers">
    One identity and one memory per customer, across every channel and
    session, ready before the agent speaks.
  </Card>
</CardGroup>

<Note>
**Then replicate it for every user.** A consumer app has millions of users;
a SaaS product, thousands of accounts. For a small team, this layer alone is
a distributed-systems problem. Unpod ships it as one system.
</Note>

## What runs today

Voice is in production on Unpod's own rails: agents and the
[agent harness](/core-engine/agent-harness), per-call customer context with
memory of past calls, and a structured outcome after every call. WhatsApp,
SMS and email conversations, cross-channel context, and journeys are in
build. Every [Core Engine](/core-engine/overview) page prints its own status.
