Unpod is fully open source under the MIT license. This means you can run the entire platform - frontend, backend, voice pipeline, and all infrastructure - on your own servers. This guide covers everything from local setup to a production-hardened deployment.

## Why Self-Host?

- **Data sovereignty**: Call recordings and transcripts never leave your infrastructure
- **Compliance**: Meet HIPAA, GDPR, or SOC 2 requirements with full control over data residency
- **Cost at scale**: For high call volumes, self-hosting can significantly reduce per-minute costs
- **Customization**: Modify the source, add integrations, and white-label the platform

---

## Architecture Overview

Unpod is a monorepo with these key services:

| Service | Tech | Port |
|---------|------|------|
| Frontend | Next.js | 3000 |
| Backend Core | Django (Python) | 8000 |
| API Services | FastAPI | 9116 |
| Real-time | Centrifugo | 8100 |
| Database | PostgreSQL | 5432 |
| Cache / Queue | Redis | 6379 |
| Storage | MongoDB | 27017 |

All services are containerized and orchestrated via Docker Compose.

## Quick Start (Development)

The fastest path to a running instance:

```bash
git clone https://github.com/unpod-ai/unpod.git
cd unpod
docker compose -f docker-compose.simple.yml up -d --build
```

Access points after startup:

| Service | URL |
|---------|-----|
| App | http://localhost:3000 |
| API | http://localhost:8000/api/v1/ |
| Admin | http://localhost:8000/unpod-admin/ |
| API Services | http://localhost:9116/docs |

Default admin email: `admin@unpod.dev`. The password is the `DJANGO_DEFAULT_ADMIN_PASSWORD` value in `docker-compose.simple.yml`.

## Environment Configuration

Copy the example env file and set your values:

```bash
cp .env.example .env
```

With `docker-compose.simple.yml`, the backend containers do not read `.env` directly (`DJANGO_READ_DOT_ENV_FILE=False`). Only the variables the compose file references as `${VAR}` - for example `POSTGRES_PASSWORD`, `OPENAI_API_KEY`, `SENDGRID_API_KEY`, `DJANGO_DEFAULT_ADMIN_PASSWORD` - are taken from `.env`; the rest are set in the compose file itself.

Critical variables to configure:

```bash
# Django
DJANGO_SECRET_KEY=your-long-random-secret-key
DJANGO_DEBUG=False

# Database
POSTGRES_DB=unpod_db
POSTGRES_USER=unpod
POSTGRES_PASSWORD=strong-password-here
DATABASE_URL=postgresql://unpod:password@postgres:5432/unpod

# Redis
REDIS_URL=redis://redis:6379/0

# Centrifugo (real-time)
CENTRIFUGO_TOKEN_HMAC_SECRET_KEY=centrifugo-secret-token
CENTRIFUGO_API_KEY=centrifugo-api-key

# AI Providers (at least one required)
OPENAI_API_KEY=sk-...
GROQ_API_KEY=gsk_...

# Voice Providers
LIVEKIT_URL=wss://your-livekit-instance.com
LIVEKIT_API_KEY=API_KEY
LIVEKIT_API_SECRET=SECRET
```

## Deploying with Docker Compose

`docker-compose.simple.yml` runs the whole stack (frontend, backend, API services, databases, Centrifugo):

```bash
docker compose -f docker-compose.simple.yml up -d --build
```

### Run Database Migrations

The `backend-core` container runs migrations and `collectstatic` on every start. To run them by hand:

```bash
docker compose -f docker-compose.simple.yml exec backend-core python manage.py migrate --no-input
docker compose -f docker-compose.simple.yml exec backend-core python manage.py collectstatic --no-input
```

### Create Admin User

```bash
docker compose -f docker-compose.simple.yml exec backend-core python manage.py createsuperuser
```

## Reverse Proxy Setup (Nginx)

Put Nginx in front of the app for SSL termination and routing:

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    # Frontend
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # Backend API
    location /api/ {
        proxy_pass http://localhost:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # WebSocket (Centrifugo)
    location /connection/websocket {
        proxy_pass http://localhost:8100;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

Use Certbot for free SSL: `certbot --nginx -d your-domain.com`

## Production Hardening Checklist

Before going live:

- [ ] Change all default passwords and secret keys
- [ ] Set `DJANGO_DEBUG=False` in all environments
- [ ] Enable PostgreSQL SSL connections
- [ ] Set up automated database backups (pg_dump to S3 or equivalent)
- [ ] Configure log rotation for Django and Nginx logs
- [ ] Set up health check endpoints for uptime monitoring
- [ ] Restrict Redis to internal network only (no public exposure)
- [ ] Use Docker secrets or a vault for API keys (not plain .env in production)

## Updating Unpod

```bash
git pull origin main
docker compose -f docker-compose.simple.yml up -d --build
docker compose -f docker-compose.simple.yml exec backend-core python manage.py migrate --no-input
```

Check the [GitHub releases](https://github.com/unpod-ai/unpod/releases) for breaking changes before pulling.
