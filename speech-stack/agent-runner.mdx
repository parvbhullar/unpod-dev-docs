The Connectivity half of the SDK. An
[AgentRunner](/get-started/core-concepts#agentrunner) is the long-lived process
that receives calls; a [Session](/get-started/core-concepts#session) is your
control surface for one live call. This page is the reference for both.

## Install

```bash
uv add unpod
uv add "unpod[dialog]"      # optional: superdialog for structured flows
uv add "unpod[langchain]"   # optional: LangChain adapter
```

Source: [unpod-ai/unpod-python-sdk](https://github.com/unpod-ai/unpod-python-sdk).

```bash
export UNPOD_API_KEY="sk_..."
export UNPOD_BASE_URL="api.unpod.ai"   # one URL; the runner derives wss://<host>
```

The [Setup Checklist](/speech-stack/setup-checklist#environment-variables)
documents every environment variable the SDK reads.

## The runner

`AgentRunner` holds a WebSocket connection to the Unpod orchestrator. When a
call is dispatched to your agent, the runner invokes your `entrypoint` with a
`CallContext`.

<Frame>
  <img src="/images/diagrams/agent-runner-dispatch.svg" alt="Animated AgentRunner dispatch diagram showing the Unpod orchestrator connected to AgentRunner over WSS, heartbeats and capacity reporting, dispatch into entrypoint CallContext, and the Session run loop." />
</Frame>

```python
from unpod import AgentRunner, CallContext

async def handle_call(ctx: CallContext) -> None:
    await ctx.session.say("Hello, thanks for calling!")
    await ctx.session.run()  # blocks until the call ends

runner = AgentRunner(
    entrypoint=handle_call,
    agent_id="my-agent",  # must match the agent_id you created the agent with
)
runner.start()  # blocking
```

<Note>
`agent_id` is the runner agent ID - a short string you choose, matching the
`agent_id` you passed to `client.agents.voice.create(...)`. Not a pipe UUID. See
[IDs You'll Meet](/get-started/core-concepts#ids-youll-meet).
</Note>

### Constructor

```python Signature
AgentRunner(
    entrypoint: Callable[[CallContext], Awaitable[None]],
    agent_id: str,
    api_key: str | None = None,            # falls back to UNPOD_API_KEY
    max_sessions: int = 50,                 # max concurrent sessions
    max_concurrent_calls: int | None = None, # alias for max_sessions
    permits_per_minute: int = 120,          # accepted but NOT enforced (see table)
    drain_timeout_s: int = 60,              # graceful shutdown window
    dev_mode: bool = False,                 # local orchestrator, dev pool
    base_url: str | None = None,            # override orchestrator URL
    serving_url: str | None = None,         # serve transport only; falls back to UNPOD_RUNNER_URL
    agent_secret: str | None = None,        # serve transport only; falls back to UNPOD_AGENT_SECRET
    transport: str = "dial_out",            # "dial_out" (v2 default) | "serve" (legacy)
)
```

| Parameter | Description |
|---|---|
| `max_sessions` | Max simultaneous sessions this runner accepts; the orchestrator will not dispatch beyond it. |
| `permits_per_minute` | Accepted for forward compatibility but **not yet enforced** - the value is stored and never read. Cap concurrency with `max_sessions` instead. |
| `drain_timeout_s` | On shutdown, wait this long for active calls to finish before force-exiting. |
| `dev_mode` | Register in a dev pool against a local orchestrator. |
| `transport` | `"dial_out"` (v2, default): the runner never listens - it dials **out** per call to the `bridge_url` delivered in the `job.assign` frame. `"serve"` (legacy, deprecated): the runner hosts a bridge server that media agents dial into. |
| `serving_url` | Public `wss://` URL of the runner's bridge server. Only used with `transport="serve"`; **ignored** (warns) under the default `dial_out` transport, which never listens. |
| `agent_secret` | Only used with `transport="serve"`: when set, inbound bridge connections are HMAC-verified; without it the runner accepts unsigned connections (dev default). **Ignored** (warns) under the default `dial_out` transport. |

### Runner lifecycle hooks

React to runner-level events (distinct from per-session hooks):

```python
@runner.on("call_start")
async def on_call_start(ctx: CallContext) -> None:
    print(f"New call: {ctx.call_id}")

@runner.on("call_end")
async def on_call_end(ctx: CallContext, final_state: str) -> None:
    print(f"Call {ctx.call_id} ended: {final_state}")
```

<Note>
This is the **runner-level** `call_end` (signature `(ctx, final_state)`), fired
once per call on the runner, with `final_state` in `"ended"` / `"failed"`. The
**session-level** `call_end` (`@ctx.session.on("call_end")`, signature
`(outcome)`) fires inside a single call with `"hangup"` / `"error"`. Neither
carries the telephony end reason - that is only readable **after** the call from
`client.calls.get(call_id).end_reason`. See
[Call Lifecycle](/speech-stack/call-lifecycle#reacting-to-outcomes-in-your-agent).
</Note>

## CallContext

Every call to your `entrypoint` receives a
[CallContext](/get-started/core-concepts#callcontext):

```python
async def handle_call(ctx: CallContext) -> None:
    ctx.call_id       # str: unique call ID
    ctx.session_id    # str: unique session ID
    ctx.agent_id      # str: the CALL's agent (from the dispatch / call.started)
    ctx.runner_id     # str: this runner's OWN configured agent_id
    ctx.direction     # str: "inbound" or "outbound"
    ctx.user_number   # str: caller's E.164 number
    ctx.instructions  # str | None: per-call override instructions
    ctx.data          # dict: metadata from dispatch (e.g. CRM data)
    ctx.session       # Session: call control object
```

<Note>
`ctx.agent_id` is the agent the **call** was dispatched for (carried on
`call.started`); `ctx.runner_id` is the agent_id this runner process was
constructed with. They match for a single-agent runner and differ for a
multi-tenant one - route on `ctx.agent_id`, not `ctx.runner_id`.
</Note>

## The Session

`ctx.session` is your interface to the live call: speak, interrupt, transfer,
record, end - all from inside your entrypoint.

### Speaking

```python
await ctx.session.say("Thank you for your patience.")   # speak via TTS, returns immediately
```

<Warning>
**Do not call `ctx.session.set_filler(...)`.** The method exists but the bridge
protocol has no filler verb, so it is delivered as an `agent.say` and the caller
**hears the sentinel `__filler:<text>` read aloud**. Configure thinking-time
fillers on the agent's [domain
dictionary](/speech-stack/domain-dictionaries#fillers) instead - that is the
supported path.
</Warning>

### Interrupting

```python
@ctx.session.on("user_turn")
async def on_user_turn(text: str) -> None:
    if "stop" in text.lower():
        await ctx.session.interrupt()   # stop the current utterance
```

### Transferring

```python
# general form
await ctx.session.transfer(
    "+15551230000",
    transfer_type="number",       # "number" | "human" | "agent"
    mode="cold",                  # "cold" | "warm"
    announcement="",              # spoken to the destination on a warm transfer
)

# shorthands - both forward mode= and announcement=
await ctx.session.transfer_to_human("tier-2-support")
await ctx.session.transfer_to_agent("billing-agent")

await ctx.session.transfer_to_human(
    "tier-2-support",
    mode="warm",
    announcement="Escalation from the billing flow.",
)
```

Either mode ends your job once the handoff succeeds.

| Mode | Behaviour |
|---|---|
| `cold` (default) | Immediate handoff, SIP REFER where the trunk supports it. |
| `warm` | An **announced** transfer, not a private consult: the destination is dialed into the **same room**, so the caller hears the ringing and the `announcement` too. |

<Warning>
Destination allowlisting is **opt-in**. Number targets are always shape-checked
as E.164, but only allowlisted when `transfer_allowed_numbers` /
`transfer_allowed_prefixes` is set in pipe config. `human` and `agent` targets
**bypass the allowlist entirely** - if a queue or agent id can reach your
session from untrusted input, validate it yourself before transferring.
</Warning>

<Tip>
`ctx.session.transfer(...)` is the in-session path and supports `mode="warm"`
directly. The out-of-band `client.sessions.transfer(...)` shown
[below](#out-of-band-session-control) does the same thing from **outside** the
call - your backend or an ops tool - when you only hold a session id.
</Tip>

### Ending

```python
await ctx.session.end(reason="completed")  # reason defaults to "completed"
```

Common reasons: `"completed"`, `"no_response"`, `"error"`, `"transferred"`,
`"max_duration"`.

### Recording control

<Warning>
**`ctx.session.recording.pause()` / `.resume()` are not implemented.** The
methods exist, but there is no recording-control verb on the bridge protocol, so
each one is delivered as an `agent.say` and the caller **hears the sentinel
(`__recording_pause:PII`, `__recording_resume`) read aloud**. Do not call them.

To keep sensitive audio out of a recording today, leave `recording=False` on
agents that handle it, or run the PII-collecting step as a separate
non-recorded agent and
[transfer](#transferring) into it.
</Warning>

### Per-call data

`session.data` is a plain dict scoped to the current call:

```python
ctx.session.data["customer"] = await crm.lookup(ctx.user_number)
```

### The main loop - `run()`

`session.run()` keeps the call alive. It reads bridge events, fires your hooks,
routes each transcribed user turn to your dialog adapter's `stream()`, and
pipes the reply tokens to TTS.

```python
async def handle_call(ctx: CallContext) -> None:
    ctx.session.dialog_machine = my_brain          # see Bring Your Agent
    await ctx.session.say("Hi, I'm Alex. How can I help?")
    await ctx.session.run()                        # blocks until call ends
    # anything here runs as post-call cleanup
```

### Live metrics

```python
m = ctx.session.metrics.live()   # CallMetrics snapshot, during or after run()
m.turns           # int: dialog turns so far
m.duration_s      # float: call duration
m.stt_p95_ms      # int: P95 STT latency
m.llm_p95_ms      # int: P95 LLM latency
m.tts_p95_ms      # int: P95 TTS latency
m.cost.voice      # float - m.cost.llm, m.cost.total
m.tokens.input    # int - m.tokens.output
m.active_llm      # str: model used on the last turn
```

<Note>
Latency/cost/token fields populate only if you feed the tracker via
`metrics.record_turn(...)` (e.g. from the `turn_complete` hook). Out of the box
only `duration_s` is meaningful - for real per-turn numbers use the `llm_call` /
`turn_complete` hooks. See [Metrics, Cost & Observability](/speech-stack/observability).
</Note>

### Session API reference

| Method | Signature | Description |
|---|---|---|
| `say` | `async (text: str) → None` | Speak text via TTS |
| `interrupt` | `async () → None` | Stop current utterance |
| `transfer` | `async (target: str, *, transfer_type: str = "number", mode: str = "cold", announcement: str = "") → None` | Transfer to a number, human queue, or agent |
| `transfer_to_human` | `async (queue: str, *, mode: str = "cold", announcement: str = "") → None` | Transfer to a human queue |
| `transfer_to_agent` | `async (agent_id: str, *, mode: str = "cold", announcement: str = "") → None` | Transfer to another agent |
| `end` | `async (reason: str = "completed") → None` | End the call |
| `run` | `async () → None` | Main event loop |
| `on` | `(event: str) → decorator` | Register hook |
| `metrics` | `property → MetricsTracker` | Per-call metrics (`.live()`) |
| `dialog_machine` | `property (get/set)` | Dialog adapter - auto-wraps superdialog types |
| `data` | `dict[str, Any]` | Per-call scratch space |

<Warning>
`set_filler`, `recording.pause` and `recording.resume` are present on `Session`
but **not implemented on the wire** - they are spoken aloud as sentinels. They
are deliberately omitted from the table above; see
[Speaking](#speaking) and [Recording control](#recording-control).
</Warning>

## Out-of-band session control

Act on a live session from outside the call - your backend, an ops tool -
via the Management SDK, targeting it by session ID:

```python
from unpod import AsyncClient

async with AsyncClient() as client:  # UNPOD_PLATFORM_TOKEN first, then UNPOD_API_KEY - see the credential table
    await client.sessions.end(session_id)

    await client.sessions.transfer(          # warm handoff supported here
        session_id,
        to_type="sip",
        to_config={"number": "+15551230000"},
        mode="warm",
        warm_handoff_ms=4000,
    )

    await client.sessions.merge(             # e.g. conference a supervisor in
        primary_session_id,
        secondary_session_ids=[other_session_id],
    )
```

## Running in production

### Monitoring

```python
s = runner.stats()        # RunnerStats snapshot
s.in_flight               # current active calls
s.capacity                # your max_sessions setting
s.completed_last_hour     # completed calls
s.failed_last_hour        # failed calls
s.mean_call_duration_s    # average call length
```

<Note>
`RunnerStats.queued` exists on the model but is **always `0`** - the runner
never queues. When it is at capacity the orchestrator simply stops dispatching
to it. Alert on `in_flight` approaching `capacity`, not on `queued`.
</Note>

### Graceful shutdown

<Warning>
**The SDK installs no signal handlers.** An unhandled `SIGTERM` terminates the
process immediately and cuts every call in flight. Draining only happens if
your code calls `await runner.shutdown()`, so install the handler yourself.
</Warning>

```python
import asyncio
import signal

from unpod import AgentRunner

async def main() -> None:
    runner = AgentRunner(entrypoint=handle_call, agent_id="my-agent", drain_timeout_s=60)

    loop = asyncio.get_running_loop()
    stopping = asyncio.Event()
    for sig in (signal.SIGTERM, signal.SIGINT):
        loop.add_signal_handler(sig, stopping.set)

    serve = asyncio.create_task(runner.run())   # run() is the async entry; start() is the blocking one
    await stopping.wait()
    await runner.shutdown()                     # drains, then returns
    serve.cancel()

asyncio.run(main())
```

Set your orchestrator's termination grace period **above** `drain_timeout_s`
(e.g. Kubernetes `terminationGracePeriodSeconds: 90` for a 60 s drain), or the
platform will `SIGKILL` you mid-drain.

<Note>
Current `shutdown()` limitations, so you can size the grace period honestly:

- It sets the shutting-down flag, then sleeps for the **full**
  `drain_timeout_s` whenever any call is in flight. There is no drain polling,
  so it does not return early when the last call ends - shutdown always costs
  the full window.
- It does not cancel jobs still running after the window; it logs which calls
  are still active and returns.
- Under `transport="serve"` it does not close the listening socket, so new
  bridge connections can still be accepted while draining. The default
  `dial_out` transport never listens and is unaffected.
</Note>

### Multiple runners

Run multiple `AgentRunner` processes with the same `agent_id` across machines.
The orchestrator load-balances on reported capacity - no shared state needed.
