## Overview

A [Number](/get-started/core-concepts#number) is the phone number callers
dial; it routes to whatever agent it is attached to. Phone numbers in
Unpod come from two sources:

- **Unpod Numbers** (default) - provision directly from the Unpod platform. No carrier account, no [trunk](#trunks), no SIP.
- **BYON (Bring Your Own Number)** - route numbers you already own from any provider over a [trunk](#trunks) you register once.

Once a number is in your account, you attach it to an `agent_id`. All inbound calls to that number are routed to that agent.

<Note>
Support for Twilio, Telnyx, and Plivo numbers is coming soon - you will be able to import numbers from these providers directly into Unpod.
</Note>

---

## Two number surfaces

The SDK exposes numbers on **two different planes**, and they do not share a
vocabulary, an identifier, or a credential. Pick one deliberately.

| | `client.telephony.numbers` | `client.numbers` |
|---|---|---|
| Plane | backend-core platform (`/api/v2/platform`) | supervoice management (`/platform`) |
| Keyed by | the **E.164 number** (`"+14155550101"`) | an opaque **`number_id`** (`num_…`) |
| Credential | `UNPOD_PLATFORM_TOKEN` / `TokenAuth` / `JWTAuth` **+ `Org-Handle`** | Bearer `UNPOD_API_KEY` works |
| `status` values | `not_assigned`, `assigned`, `closed` | whatever the pool row carries - see the warning below |
| Batch attach | Yes, with per-number `ok`/`error` | No, one number per call |
| Status | **Primary** - the SDK's own reference calls attach-to-agent the primary flow | Works for `list` / `attach` / `detach` / `sync`; `delete()` and `release()` target routes that do not exist |

This page documents `client.numbers`, which is what most quickstarts use because
a plain API key is enough. For batch attach, `connection_state`, and the
cross-plane `overview()`, use
[the telephony namespace](/speech-stack/telephony-sdk).

<Warning>
**`client.numbers.list()` reads the platform pool, not supervoice.** Two
consequences that bite the first script you write:

- `status` arrives **verbatim from the platform** as `NOT_ASSIGNED` / `ASSIGNED`
  / `CLOSED` (the model accepts a raw `state` key under the `status` name and
  otherwise defaults to `available`). `active`, `inactive` and `pending` are
  **not** values either plane emits - `list(status="active")` matches nothing.
- `pipe_id` is **absent** from pool rows, so `n.pipe_id is None` is true for
  **every** row and tells you nothing about whether a number is free.

Compare `status` case-insensitively against both vocabularies, and do not use
`pipe_id` as a free/attached test:

```python
FREE = {"not_assigned", "available"}
free = [n for n in await client.numbers.list() if (n.status or "").lower() in FREE]
```
</Warning>

## Getting Numbers from Unpod

Numbers provisioned through Unpod are immediately available in your account. You can browse and acquire them from the dashboard under **Dev Platform -> Numbers**.

Once provisioned, list them via the SDK:

```python
import asyncio
from unpod import AsyncClient

async def main():
    async with AsyncClient() as client:
        numbers = await client.numbers.list()
        for n in numbers:
            print(n.number_id, n.number, n.status)

asyncio.run(main())
```

## Trunks

A [Trunk](/get-started/core-concepts#trunk) is your carrier connection - the SIP
capacity numbers ride on. Bring your own carrier (Twilio, Tata, …), register it
once with its SIP credentials, then work with numbers, not SIP. BYON numbers
arrive this way.

<Steps>
  <Step title="Add the trunk">
    **Dev Platform -> Telephony -> Add Trunk -> BYO SIP**. Provide the carrier's
    **SIP domain** (e.g. `sip.your-carrier.com`) and **auth username / password**.
  </Step>
  <Step title="Point the carrier at Unpod">
    Set inbound routing to the Unpod SIP endpoint shown in the dashboard.
  </Step>
  <Step title="Sync">
    Click **Sync** on the trunk, or run `await client.numbers.sync()`. The trunk's
    numbers appear in your account, ready to attach to an [agent](/speech-stack/agents).
  </Step>
</Steps>

### Register a trunk via the SDK

Field names match the dashboard.

```python
from unpod import AsyncClient
from unpod.models import TrunkCreate, ByoConfigCreate

client = AsyncClient()

trunk = await client.trunks.create(TrunkCreate(
    name="tata-byo",
    type="byo",
    byo_config=ByoConfigCreate(
        provider="tata",
        sip_domain="sip.tata.in",
        auth_username="user",
        auth_password="secret",
        transport="tls",   # default
    ),
))
```

### List and delete trunks

```python
trunks = await client.trunks.list()
await client.trunks.delete(trunk.trunk_id)
```

### Sync numbers off a trunk

```python
result = await client.numbers.sync()   # {"synced": int, "new": int}
```

[Provisioning checklist](/speech-stack/setup-checklist).

## Listing Numbers

```python
import asyncio
from unpod import AsyncClient

async def main():
    async with AsyncClient() as client:  # Bearer UNPOD_API_KEY is fine on this plane
        numbers = await client.numbers.list()
        us_numbers = await client.numbers.list(country="US")
        byon = await client.numbers.list(trunk_type="byo")

        for n in numbers:
            print(n.number_id, n.number, n.status)

asyncio.run(main())
```

<Note>
`list()` also accepts `status=`, but pass it a value the plane actually emits
(`"NOT_ASSIGNED"`, `"ASSIGNED"`, `"CLOSED"`) - or omit it and filter in Python,
which is what the examples below do. `country=` and `trunk_type=` are applied
server-side.
</Note>

### Number fields

| Field | Type | Description |
|---|---|---|
| `number_id` | `str` | Unique number ID (`num_...`), aliased from `id`. Also readable as `.id` |
| `number` | `str` | E.164 format, e.g. `+14155550100` |
| `status` | `str` | Defaults to `available`; accepts a raw `state` key, so a pool row lands here as `NOT_ASSIGNED` / `ASSIGNED` / `CLOSED`. supervoice's own vocabulary is `available` / `assigned` / `in_call` / `disabled`. **Compare case-insensitively** |
| `trunk_type` | `str` | `livekit` (default), `unpod`, or `byo` |
| `trunk_id` | `str \| None` | The trunk this number rides on |
| `pipe_id` | `str \| None` | The agent-voice row this number is attached to. **Absent on pool rows from `list()`**, so `None` does not mean "free" there |
| `active_call_id` | `str \| None` | Set while the number is mid-call |
| `country` | `str \| None` | ISO 3166-1 alpha-2 country code |
| `capabilities` | `list[str]` | e.g. `["voice"]` |

## Attaching a Number to an Agent

A number can be attached to exactly one agent at a time. Inbound calls to that
number are routed to that agent.

```python
import asyncio
from unpod import AsyncClient

async def main():
    async with AsyncClient() as client:
        number = await client.numbers.attach("num_...", "support-bot")
        print("Attached:", number.number, "-> agent support-bot")

asyncio.run(main())
```

### `attach()` parameters

| Parameter | Type | Description |
|---|---|---|
| `number_id` | `str` | The number's id (`num_...`) |
| `agent_id` | `str` | The agent to route calls to |
| `number` | `str \| None` | The E.164, optional. Pass it when `number_id` is a supervoice id so telephony can resolve the row it owns |

<Warning>
`attach()` used to take **`pipe_id=`**. It takes `agent_id` now - supervoice
stopped storing a pipe pin and resolves the pipe from the agent instead. Old
calls raise a `TypeError`.
</Warning>

`client.agents.numbers.attach(agent_id, number)` does the same job keyed by the
E.164 number rather than the number id - see [Agents](/speech-stack/agents).

<Note>
This attach posts to the speech endpoint
(`/api/v2/platform/speech/v1/numbers/{id}/attach`), which delegates to the
platform's attach orchestration - it creates the voice-bridge number and the
LiveKit trunks and pushes the ids back to supervoice. To attach **several**
numbers in one request, or to read the resulting SBC `connection_state`, use
[`client.telephony.numbers.attach()`](/speech-stack/telephony-sdk#attach-numbers-to-an-agent).
</Note>

<Warning>
`client.numbers.delete()` and `client.numbers.release()` both target
`DELETE /api/v2/platform/telephony/numbers/{id}`, which **is not a live route**.
To free a number, `detach()` it - the record is released and stays available for
a later attach.
</Warning>

## Common Patterns

### Find the first free number and attach it

```python
import asyncio
from unpod import AsyncClient

# The pool reports NOT_ASSIGNED; a supervoice row reports available. Accept both.
FREE_STATUSES = {"not_assigned", "available"}

async def attach_first_free(agent_id: str) -> None:
    async with AsyncClient() as client:
        numbers = await client.numbers.list()
        free = [n for n in numbers if (n.status or "").lower() in FREE_STATUSES]
        if not free:
            raise RuntimeError("No free numbers available")
        await client.numbers.attach(free[0].number_id, agent_id, number=free[0].number)
        print("Attached", free[0].number)

asyncio.run(attach_first_free("support-bot"))
```

<Tip>
Do **not** write `if n.pipe_id is None` here - pool rows never carry `pipe_id`,
so that filter passes everything, including numbers already attached to another
agent. Filter on `status`.
</Tip>

### Rotate numbers across agents

```python
import asyncio
from unpod import AsyncClient

async def rotate(numbers: list[str], agents: list[str]) -> None:
    async with AsyncClient() as client:
        for num_id, agent_id in zip(numbers, agents):
            await client.numbers.attach(num_id, agent_id)
            print(f"{num_id} -> {agent_id}")

asyncio.run(rotate(["num_a", "num_b"], ["support-bot", "sales-bot"]))
```
