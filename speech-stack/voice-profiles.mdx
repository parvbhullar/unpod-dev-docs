## What Is a Voice Profile?

A [Voice Profile](/get-started/core-concepts#voice-profile) bundles three
things into a single reusable configuration:

- **Speech-to-Text (STT)** - transcribes the caller's audio into text
- **Text-to-Speech (TTS)** - converts agent text into natural-sounding audio
- **Voice** - the specific voice identity (gender, accent, character) used for TTS output

When you attach a voice profile to an agent, every call that voice handles uses that configuration automatically - including failover if a provider goes down.

<Frame>
  <img src="/images/diagrams/voice-profile-pipeline.svg" alt="Voice profile pipeline diagram showing caller speech passing through STT, dialog machine text handling, TTS plus voice, and caller playback." />
</Frame>

Voice profiles are managed by Unpod. You browse and select from the available list - you do not configure STT/TTS providers directly. The resource is **read-only**: only `list()` and `get()` exist.

<Warning>
**`client.voice_profiles` needs a platform credential, not an API key.** It
reads backend-core's `/api/v2/platform/voice-profiles/` - the same plane as
[`client.telephony`](/speech-stack/telephony-sdk) and `client.analytics` - so a
bare Bearer `UNPOD_API_KEY` is **refused**. Set `UNPOD_PLATFORM_TOKEN` (plus
`UNPOD_ORG_HANDLE`), or pass `auth=` explicitly:

```python
import os
from unpod import AsyncClient, JWTAuth

# Option A: environment. AsyncClient() prefers UNPOD_PLATFORM_TOKEN over UNPOD_API_KEY.
#   export UNPOD_PLATFORM_TOKEN="..."
#   export UNPOD_ORG_HANDLE="acme"

# Option B: explicit
client = AsyncClient(auth=JWTAuth(os.environ["UNPOD_JWT"], org_handle="acme"))
```

See [Client, Auth & Planes](/speech-stack/client-auth) for the full credential
matrix.
</Warning>

## Listing Voice Profiles via SDK

```python
import asyncio
from unpod import AsyncClient

async def main():
    # UNPOD_PLATFORM_TOKEN (+ UNPOD_ORG_HANDLE) - an API key alone is refused here
    async with AsyncClient() as client:
        profiles = await client.voice_profiles.list()

        for p in profiles:
            print(
                p.profile_id,
                p.name,
                f"gender={p.gender}",
                f"quality={p.quality}",
            )

asyncio.run(main())
```

<Warning>
**`language=` is a no-op.** The SDK sends `?language=en`, but the backing view
ignores query parameters, so you get the full list back either way. You have to
filter in Python.

**Do not filter on `p.languages` alone.** It is a real field, but it defaults to
`[]` and real responses usually leave it empty - the language codes arrive
inside the nested `voice` and `transcriber` dicts instead (the model allows
extra fields, so they are there). Filtering on the flat field alone silently
matches nothing.

```python
def speaks(profile, code: str) -> bool:
    """True when a profile covers `code`, wherever the response put it."""
    if code in (profile.languages or []):
        return True
    if (profile.language or "") == code:
        return True
    # Real responses carry the codes in the nested provider dicts, e.g.
    # voice={"languages": [{"code": "en"}, {"code": "hi"}]}
    for block in ("voice", "transcriber"):
        nested = getattr(profile, block, None) or {}
        for entry in nested.get("languages") or []:
            value = entry.get("code") if isinstance(entry, dict) else entry
            if value in (code, "multi"):
                return True
    return False
```

```python
profiles = await client.voice_profiles.list()
en_profiles = [p for p in profiles if speaks(p, "en")]
```

Print one profile first (`print(profiles[0])`) to see the shape your deployment
returns before committing to a filter.
</Warning>

### VoiceProfile fields

| Field | Type | Description |
|---|---|---|
| `profile_id` | `str` | Profile ID to pass as `voice_profile` when creating an agent |
| `name` | `str` | Human-readable name, e.g. `"Emma (HD)"` |
| `gender` | `str` | `male`, `female`, or `neutral` |
| `quality` | `str` | `standard` or `high` |
| `languages` | `list[str]` | Supported language codes, e.g. `["en", "hi"]` |
| `description` | `str \| None` | Short description of the voice character |
| `latency_ms` | `int \| None` | Expected end-to-end latency in milliseconds |
| `greeting_message` | `str \| None` | Default greeting for this profile |

## Getting a Single Profile

```python
import asyncio
from unpod import AsyncClient

async def main():
    async with AsyncClient() as client:  # platform credential, as above
        profile = await client.voice_profiles.get("vp_en_female_hd")
        print(profile.name, profile.quality, profile.languages)

asyncio.run(main())
```

## Choosing the Right Profile

### By use case

| Use case | Recommended qualities |
|---|---|
| Customer support | High quality, natural voice, low latency |
| Sales outreach | Expressive, high quality, brand-matched |
| Appointment booking | Standard quality - lower latency |
| Multilingual | Match language codes to caller's region |

### By latency

Total call latency has three components: STT transcription + LLM thinking + TTS synthesis.

- Choose `quality == "high"` when voice naturalness matters more than speed
- Choose `quality == "standard"` for latency-sensitive or high-volume deployments
- Check `latency_ms` on the profile object for the estimated end-to-end figure

## Using a Profile When Creating an Agent

Pass `profile_id` as `voice_profile` when you create the agent:

```python
import asyncio
from unpod import AsyncClient, Prompt

async def main():
    async with AsyncClient() as client:  # platform credential, as above
        # List, then filter in Python - the language= kwarg is not applied server-side
        profiles = await client.voice_profiles.list()
        hd_female = next(
            p
            for p in profiles
            if speaks(p, "en") and p.quality == "high" and p.gender == "female"
        )

        voice = await client.agents.voice.create(
            "support-bot",
            brain=Prompt("You are a concise support assistant."),
            name="Support Bot",
            voice_profile=hd_female.profile_id,
        )
        print("Created agent with profile:", voice.voice_profile_name)

asyncio.run(main())
```

## Giving an Agent a Second Voice

One agent, one brain, many voices - a second language is a second voice, not a
second agent. The new voice inherits the brain unchanged.

```python
import asyncio
from unpod import AsyncClient

async def main():
    async with AsyncClient() as client:
        await client.agents.voice.add(
            "support-bot",
            voice_profile="vp_es_male_std",     # Spanish male
            greeting="Hola, gracias por llamar.",
        )

        agent = await client.agents.get("support-bot")
        for v in agent.voices:
            print(v.voice_profile_id, v.voice_profile_name, v.is_default)

        # Drop one voice; the agent keeps the rest
        await client.agents.voice.remove("support-bot", "vp_es_male_std")

asyncio.run(main())
```
