Own your model starts with **definable blocks**: a block takes communication
in and writes structure out - extraction, qualification & scoring,
summarization, sentiment & intent, evaluation, or a custom block you define.
A block is attached to an agent and runs on every session that agent
finishes; each run is stored as a result against the call, so you can read
it back or receive it with the call.

## The primitives

| Primitive | What it is | Where it lives today |
|---|---|---|
| Blocks | A defined unit of analysis (extraction, scoring, summarization, sentiment & intent, evaluation, custom): a prompt plus typed fields, attached to an agent | Extraction, scoring, and summarization run on call outcomes - see [Post-call data](/api/post-call-data). SDK agents define their own with `client.analytics.create()` and attach them with `client.analytics.attach()` - see [Analytics](/speech-stack/analytics) |
| Evaluations | Blocks that score whether a conversation did its job | A block's success evaluation (`success_enabled`, on by default) scores each call; [SuperDialog evals](/superdialog/evals) score conversations against ratified expectations |

## On the spine

Blocks read the finished call's transcript after the call ends; they never
touch the audio path. What a block produces is stored as a result on the
[outcome](/intelligence/outcomes) it analyzed - read it with
`client.analytics.for_call(call_id)` - and the post-call webhook carries
every attached block's result, so your system receives it as ordinary data,
not as a side channel.

## What stays hidden

How a block runs. You write a block's prompt and fields (and can pick its
model) and ratify evaluations; the pipeline that runs it is not a surface you
configure.

## Status

- Definable blocks: extraction, scoring, and summarization run on call
  outcomes in production via [Post-call data](/api/post-call-data), and
  SDK agents author them with [`client.analytics`](/speech-stack/analytics).
- Evaluations: each block's success evaluation, and conversation-level evals
  through [SuperDialog evals](/superdialog/evals).
