A per-number lifecycle overview for your organization: one row per `ASSIGNED` number on
your bridges, exposing `connection_state`, termination kind, agent link, and the
projection `sync_state`. This endpoint is DB-only - it never live-probes the projection
planes, so it stays fast and never errors on a missing projection. Secrets are masked.

<Note>
**Prerequisites:** API Token + Org-Handle. See [Authentication](/api/get-started/authentication).
</Note>

### Headers

| Name          | Type   | Required | Description                          |
|---------------|--------|----------|--------------------------------------|
| Authorization | string | Yes      | `Token <your-api-key>`               |
| Org-Handle    | string | Yes      | Organization domain handle           |
| Product-Id    | string | No       | Optional product filter              |

### Row fields

| Field            | Type    | Description                                  |
|------------------|---------|----------------------------------------------|
| number_id        | integer | Number id                                    |
| number           | string  | E.164 number                                 |
| bridge_slug      | string  | Bridge the number is on                      |
| connection_state | string  | `NOT_LINKED`, `PENDING_VERIFY`, `LINKED` or `ERROR` ([Number states](/telephony/apis/numbers#number-states)) |
| termination_kind | string  | `sip` (your SIP trunk or SIP endpoint), `livekit`, or `null`. Unpod pool numbers read `null`, including ones attached to an agent |
| agent_id         | string  | Linked agent handle (null for carrier)       |
| provider         | string  | Provider name of the number's credential (nullable) |
| provider_credential_id | integer | Id of that credential (nullable); secrets are never returned |
| sync_state       | string  | `in_sync`, `out_of_sync` (a push failed; Unpod retries) or `drift` (not yet on every plane). Nullable |
| sync_detail      | object  | Extra sync detail (nullable)                 |
| in_sync          | boolean | `true` when `sync_state` is `in_sync`         |
