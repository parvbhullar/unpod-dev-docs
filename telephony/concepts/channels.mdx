Channels are how an agent reaches a person. Today an Unpod agent talks over
**voice** and **web chat**, and can send a template **SMS** during a call.

Two kinds of connector, and the distinction matters. **Channel connectors**
carry conversations - they deliver messages to a person and back. **System
connectors** (Google Sheets and Shopify) push and pull rows - they sync
records but never carry a conversation. A Sheets sync updates rows; a chat
message extends a conversation.

## The primitives

| Primitive | What it is | Where it lives |
|---|---|---|
| Messages | One unit of content on a channel - a chat turn, an in-call SMS | Web chat via the [Chat API](/get-started/chat) |
| Identities | The per-channel addresses (phone number, email address) that resolve to one person | [Entities](/intelligence/entities) |
| Connectors | The bindings to each channel provider - and to systems like Google Sheets and Shopify, which sync rows rather than carry conversations | Per channel; see [Channels today](#channels-today) |
| Routing | Which number and which agent handles the call | Voice routing in [Telephony](/telephony/introduction) |

Voice is a channel too - the largest one. It has its own component page
because the rails underneath it are deep: see the
[Calling Engine](/telephony/concepts/calling-engine).

## Channels today

- **Voice** - via the [Calling Engine](/telephony/concepts/calling-engine).
- **Web chat** - through the [Chat API](/get-started/chat): text in, text
  out; you render the UI.
- **SMS** - an in-call action: the agent sends a template SMS during a call.
