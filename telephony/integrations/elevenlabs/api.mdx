The **programmatic** path. This is the **hybrid** model: a **SIP trunk** carries the
audio to ElevenLabs, and an **ElevenLabs provider configuration** (your ElevenLabs API
key) lets Unpod manage the agent side. Prefer clicks? See the
[Dashboard guide](/telephony/integrations/elevenlabs/dashboard).

<Note>
**Base URL:** `https://unpod.ai/api/v2/platform/`
Every request needs `Authorization: Token <your-api-key>` and an `Org-Handle` header.
See [Authentication](/api/get-started/authentication).
</Note>

## Prerequisites

- An Unpod **API Token** and **Org-Handle**.
- A **number** in your org — note its `number_id` (and a **Bridge** `slug`).
- An ElevenLabs **API Key** (ElevenLabs Dashboard → Profile → API Keys) and a
  **Conversational AI agent** (with a First Message + voice).

## 1. Create the SIP trunk to ElevenLabs

Point the trunk's `sip_url` at ElevenLabs' SIP host.

```bash cURL
curl -X POST https://unpod.ai/api/v2/platform/telephony/trunks/ \
  -H "Authorization: Token $UNPOD_TOKEN" \
  -H "Org-Handle: $ORG_HANDLE" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "ElevenLabs trunk",
    "sip_url": "sip:sip.rtc.elevenlabs.io:5060;transport=tcp",
    "transport": "tcp",
    "port": "5060"
  }'
```

```json Response (201)
{
  "status_code": 201,
  "message": "Trunk created successfully.",
  "data": { "id": 21, "name": "ElevenLabs trunk", "sip_url": "sip:sip.rtc.elevenlabs.io:5060;transport=tcp", "transport": "tcp", "port": "5060", "active": true }
}
```

<Tip>Copy the returned trunk `id` — you need it in the next step.</Tip>

## 2. Attach your number to the trunk

```bash cURL
curl -X POST https://unpod.ai/api/v2/platform/telephony/trunks/21/attach-numbers/ \
  -H "Authorization: Token $UNPOD_TOKEN" \
  -H "Org-Handle: $ORG_HANDLE" \
  -H "Content-Type: application/json" \
  -d '{ "number_ids": [501] }'
```

```json Response (201)
{
  "status_code": 201,
  "message": "Numbers mapped to trunk.",
  "data": {
    "trunk_id": 21,
    "origin_endpoint": {
      "ingress": "sip:sip-lb1.unpod.tel",
      "dids": ["+918071539111"],
      "accepted_source_ips": [],
      "region": "ap-south"
    }
  }
}
```

The `origin_endpoint.ingress` is the **address you give ElevenLabs** for the outbound
trunk in step 5.

## 3. Register the ElevenLabs provider (API key)

This stores your ElevenLabs API key so Unpod can manage the agent side.

```bash cURL
curl -X POST https://unpod.ai/api/v2/platform/telephony/providers-configurations/ \
  -H "Authorization: Token $UNPOD_TOKEN" \
  -H "Org-Handle: $ORG_HANDLE" \
  -H "Content-Type: application/json" \
  -d '{
    "provider": "elevenlabs",
    "account_sid": "my-elevenlabs-config",
    "auth_token": "<YOUR_ELEVENLABS_API_KEY>"
  }'
```

```json Response (201)
{
  "status_code": 201,
  "message": "Provider configuration created successfully.",
  "data": { "id": 47, "provider": "elevenlabs", "created_at": "2026-02-07T10:00:00Z" }
}
```

## 4. Connect the provider configuration to your Bridge

```bash cURL
curl -X POST \
  https://unpod.ai/api/v2/platform/telephony/bridges/$BRIDGE_SLUG/connect-provider/ \
  -H "Authorization: Token $UNPOD_TOKEN" \
  -H "Org-Handle: $ORG_HANDLE" \
  -H "Content-Type: application/json" \
  -d '{ "provider_config_id": 47 }'
```

## 5. Finish on the ElevenLabs side

In ElevenLabs **Agents → Phone Numbers → Import a phone number from SIP trunk**:

- **Phone Number** — your Unpod number (E.164).
- **Outbound trunk → Address** — the `origin_endpoint.ingress` from step 2
  (hostname only, no `sip:` prefix, e.g. `sip-lb1.unpod.tel`), Transport `TCP`.
- **Attach** your Conversational AI **agent**.

See the [Dashboard guide](/telephony/integrations/elevenlabs/dashboard) for the full
ElevenLabs-side screens.

## Troubleshooting

| Status / symptom | Meaning | Fix |
|---|---|---|
| `400` on `/trunks/` | Missing `sip_url` | Send `sip:sip.rtc.elevenlabs.io:5060;transport=tcp` |
| `400` on attach | Number not in org | Use a valid `number_id` from your org |
| `400` on provider config | Invalid ElevenLabs key | Re-check `auth_token` |
| `401` | Bad Unpod token | Verify `Authorization: Token …` |
| `409` | Config already exists | Reuse the existing `provider_config_id` |
| Inbound silent | Agent missing First Message/voice | Set both on the ElevenLabs agent |
