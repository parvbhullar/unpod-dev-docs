# Create Bridge

Create a new telephony bridge for call routing. Bridges are the core routing entities that link telephony providers and phone numbers to your Voice AI agents.

An organization has one bridge. If yours already has one, this call doesn't create a second bridge: it applies `name`, `description`, `region` and `status` to the existing bridge and returns it.

<Note>
**Prerequisites:** Make sure you have your API Token and Org-Handle ready. See [Authentication](/api/get-started/authentication) for details.
</Note>

---

### Headers

| Name          | Type   | Required | Description                     |
|---------------|--------|----------|---------------------------------|
| Authorization | string | Yes      | API Key format: `Token <token>` |
| Org-Handle    | string | Yes      | Organization domain handle      |
| Product-Id    | string | No       | Product the bridge belongs to, for example `unpod.ai`. [Get All Bridges](/api/telephony/get-all-bridges) lists bridges by this value |
| Content-Type  | string | Yes      | `application/json`              |

<Note>
Copy your `Org-Handle` from the dashboard - see [How to Get Your Organization Handle](/api/get-started/authentication#how-to-get-your-organization-handle).
</Note>

### Request Body

| Field | Type   | Required | Description                                 |
|-------|--------|----------|---------------------------------------------|
| name        | string | Yes      | Display name for the bridge                 |
| description | string | No       | Bridge description                          |
| region      | string | No       | `IN` (default), `US`, `EU`, `AUS`, or `UAE` |
| status      | string | No       | `ACTIVE`, `INACTIVE`, or `DRAFT` (default)  |
| slug        | string | No       | URL-friendly identifier. Generated from the name when omitted |


### Response Fields

| Field       | Type    | Description            |
|-------------|---------|------------------------|
| status_code | integer | HTTP status code       |
| message     | string  | Response message       |
| data        | object  | Created bridge details |

### Bridge Object Fields

| Field      | Type    | Description                         |
|------------|---------|-------------------------------------|
| id                   | integer | Bridge unique identifier             |
| name                 | string  | Bridge display name                  |
| description          | string  | Bridge description                   |
| status               | string  | `ACTIVE`, `INACTIVE`, or `DRAFT`     |
| documents_status     | string  | Document processing status           |
| slug                 | string  | Unique bridge slug identifier        |
| numbers              | array   | Numbers on the bridge                |
| organization         | integer | ID of the owning organization        |
| region               | string  | Bridge region                        |
| organization_details | object  | Details of the owning organization (not shown in the example) |

---

## Common Error Codes

| Status Code | Description                                      |
|-------------|--------------------------------------------------|
| 201         | Created - Bridge created successfully            |
| 400         | Bad Request - Missing `Org-Handle` or invalid body (details in `message`) |
| 401         | Unauthorized - Invalid or missing API token      |
| 403         | Forbidden - Not a member of the organization     |
| 500         | Internal Server Error - Server-side error        |

## Code Examples

<CodeGroup>

```javascript Node.js
const axios = require('axios');

const headers = {
  'Authorization': 'Token your-api-token',
  'Org-Handle': 'your-org-handle',
  'Content-Type': 'application/json'
};

// Create a new telephony bridge
const createBridge = async (name, slug) => {
  const response = await axios.post(
    'https://unpod.ai/api/v2/platform/telephony/bridges/',
    { name, slug },
    { headers }
  );
  console.log(`Bridge created: ${response.data.data.slug} (ID: ${response.data.data.id})`);
  return response.data.data;
};

// Example usage
createBridge('Sales Bridge', 'sales-bridge-001');
```

```python Python
import requests

headers = {
    'Authorization': 'Token your-api-token',
    'Org-Handle': 'your-org-handle',
    'Content-Type': 'application/json'
}

def create_bridge(name: str, slug: str):
    """Create a new telephony bridge"""
    url = 'https://unpod.ai/api/v2/platform/telephony/bridges/'
    payload = {'name': name, 'slug': slug}
    response = requests.post(url, headers=headers, json=payload)
    data = response.json()
    print(f"Bridge created: {data['data']['slug']} (ID: {data['data']['id']})")
    return data['data']

# Example usage
create_bridge('Sales Bridge', 'sales-bridge-001')
```

```bash cURL
# Create a new telephony bridge

  -H "Org-Handle: your-org-handle" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Sales Bridge",
    "slug": "sales-bridge-001"
  }'
```

## Best Practices

1. **Slug Naming**: Use descriptive, lowercase slugs (e.g., `sales-outbound-us`) to easily identify bridges
2. **One Bridge**: Call [Get All Bridges](/api/telephony/get-all-bridges) first - your organization may already have its bridge
3. **Post-Creation**: After creating a bridge, use [Connect Provider to Bridge](/api/telephony/connect-provider-to-bridge) to link a telephony provider
4. **Bridge ID**: Store the returned `id` and `slug` for subsequent bridge management operations
5. **Error Handling**: Handle 400 responses and read the `message` field
6. **Security**: Keep API tokens secure and rotate them regularly
